# Prime Connect — نظام الموظفين والعملاء والتوظيف (CRM)

نظام ويب بالعربي، شغال من الموبايل والكمبيوتر، فيه تسجيل دخول وصلاحيات لكل موظف.

## فيه إيه
- **لوحة التحكم:** أرقام سريعة، انترفيوهات جاية، وبحث سريع عن مرشحين لوظيفة معينة.
- **الوظائف:** قائمة الوظائف اللي بتشتغلوا عليها.
- **المرشحين (بنك المرشحين):** الاسم، الرقم، الوظيفة، المهارات، الحالة.
- **العملاء (الشركات):** اضغط على أي شركة يفتح **ملف الشركة**: طلباتها، والمرشحين ليها، عمل انترفيو ولا لأ، اتقبل ولا اترفض، والمرتب. وفيه زراير اتصال وواتساب.
- **طلبات الشركات:** كل طلب توظيف من شركة (الوظيفة، العدد المطلوب، المرتب المعروض، الحالة).
- **الترشيحات:** بتربط مرشح بطلب شركة، وتقدر تضيف مرشح جديد من نفس الفورم.
- **التوظيفات والعمولات:** المرشح اللي اتقبل يظهر جنبه زرار "سجّل كتوظيف".
- **تصدير Excel:** شيت ملخص، وشيت لكل شركة.
- **الحسابات والصلاحيات:** المالك بيعمل حساب لكل موظف ويحدد صلاحياته، ويقدر يغيّر كلمة مرور أي موظف.
- **تغيير كلمة المرور:** كل واحد يغيّر كلمة المرور بتاعته من زرار "كلمة المرور" اللي فوق.
- **حماية:** لو حد كتب كلمة مرور غلط 10 مرات، الحساب بيتقفل ربع ساعة.

## الحسابات والصلاحيات
- **الحساب الرئيسي (المالك):** بيتعمل أوتوماتيك أول مرة السيستم يشتغل، من `ADMIN_USERNAME` و`ADMIN_PASSWORD`. عنده كل الصلاحيات، ومحدش يقدر يعدّله أو يمسحه.
- **حسابات الموظفين:** بتبدأ بصلاحيات بسيطة، والمالك بيفعّل أو يلغي أي صلاحية من تاب "الحسابات والصلاحيات".

## خطوات الرفع على Render

### 1) اعمل قاعدة بيانات مجانية على Neon (علشان البيانات ماتضيعش)
على باقة Render المجانية، أي ملف على السيرفر بيتمسح مع كل تحديث أو إعادة تشغيل. علشان كده البيانات بتتحفظ في قاعدة بيانات Postgres.
1. ادخل على https://neon.tech واعمل حساب، تقدر تدخل بحساب GitHub.
2. اعمل Project جديد، واختار أقرب منطقة ليك، مثلاً Frankfurt.
3. من **Connection string** انسخ الرابط. هيكون شكله كده:
   `postgresql://user:password@ep-xxxx.eu-central-1.aws.neon.tech/neondb?sslmode=require`
4. احتفظ بيه، هتحتاجه في خطوة 3.

> ممكن تستخدم Render Postgres بدل Neon، بس النسخة المجانية منه بتتمسح بعد 30 يوم. Neon المجاني مش بينتهي.

### 2) الكود على GitHub
الكود موجود في الـ repository ده. لو حبيت تعدّل حاجة، عدّلها هنا وRender هيحدّث لوحده.

### 3) اعمل الخدمة على Render
1. ادخل على https://render.com وسجّل دخول بحساب GitHub.
2. اختار **New → Blueprint**، واختار الـ repository `prime-connect`. Render هيقرا ملف `render.yaml` ويجهز كل حاجة.
3. هيطلب منك تكتب 3 قيم:
   - `ADMIN_USERNAME`: اسم المستخدم اللي هتدخل بيه كمالك، مثلاً `hesham`.
   - `ADMIN_PASSWORD`: كلمة مرور قوية.
   - `DATABASE_URL`: الرابط اللي نسخته من Neon.
4. دوس **Apply**. بعد دقيقتين تقريبًا هيديك رابط زي `prime-connect.onrender.com`.

> `SESSION_SECRET` بيتعمل أوتوماتيك، ومش محتاج تعمل فيه حاجة.

**لو عايز تعملها يدوي بدل Blueprint:** اختار New → Web Service واربطه بالـ repo، وبعدين:
- Build Command: `npm install`
- Start Command: `npm start`
- Environment Variables:
  - `NODE_ENV` = `production`
  - `SESSION_SECRET` = أي نص عشوائي طويل
  - `ADMIN_USERNAME`
  - `ADMIN_PASSWORD`
  - `DATABASE_URL`

### 4) أول دخول
1. افتح الرابط وسجّل دخول بحساب المالك.
2. روح تاب **الحسابات والصلاحيات**، واعمل حساب لكل موظف وحدد صلاحياته.
3. ابدأ بإضافة الشركات من تاب **العملاء**، وبعدين طلباتهم من تاب **طلبات الشركات**.

### 5) دومين خاص بيك (اختياري)
1. من إعدادات الخدمة على Render اختار **Custom Domains** وضيف الدومين، مثلاً `crm.primebridge.com`.
2. Render هيديك سجل DNS من نوع CNAME، ضيفه عند الشركة اللي اشتريت منها الدومين.
3. الـ HTTPS بيتفعّل أوتوماتيك.

### ملاحظات
- على الباقة المجانية، السيرفر بينام لو محدش فتحه 15 دقيقة، وأول فتحة بعدها بتاخد حوالي 30 ثانية. لو مضايقك، الباقة المدفوعة Starter بتحل ده.
- `ADMIN_USERNAME` و`ADMIN_PASSWORD` بيتقروا مرة واحدة بس، أول تشغيل. بعد كده غيّر كلمة المرور من جوه السيستم.
- لما السيرفر يعيد التشغيل، كل الناس بتحتاج تسجل دخول تاني. البيانات نفسها مابتتأثرش.

## تشغيل السيستم على جهازك للتجربة
```
npm install
ADMIN_USERNAME=admin ADMIN_PASSWORD=YourStrongPassword npm start
```
هيشتغل على http://localhost:3000. من غير `DATABASE_URL` البيانات بتتحفظ في ملف `data.json` على جهازك.
